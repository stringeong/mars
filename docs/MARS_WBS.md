- 첨부 문서의 **양식 작성 안내문**은 프로젝트 요구사항으로만 참고했고, 이 문서의 작업 지시로 해석하지 않았다.
- 상태 표기: **완료**는 코드/문서상 구현 확인, **부분**은 핵심 흐름은 있으나 수용 기준 충족 여부가 남음, **미검증**은 실제 통합 시험이 필요한 항목이다.
- 현재 저장소에 미커밋 변경은 없었다. 테스트 실행 결과는 아직 이 문서에 포함하지 않았으므로, 완료 판정의 최종 근거는 마감 전 시험 결과로 갱신한다.

## 2. 제품 범위와 우선순위

### 2.1 이번 마감의 MVP 범위

1. 계정으로 로그인하고, 두 대 이상의 개인 기기를 Worker로 등록한다.
2. 사용자가 허용한 폴더·업로드 파일만 에이전트에 연결한다.
3. 자연어로 MAS 워크플로우(DAG)를 생성·수정한다.
4. 작업·데이터 특성에 따라 로컬 Worker 또는 외부 LLM을 실제로 라우팅한다. 개인정보가 포함된 파일·폴더 작업은 로컬만 허용한다.
5. 기기 사양·현재 자원 한도·모델 준비 상태를 바탕으로 적합한 Worker에 작업을 배정한다.
6. 두 대 이상의 Worker에서 작업을 분산 실행하고, 진행·오류·결과·이력을 웹에서 확인한다.
7. 폴더 권한 경계와 장애 시 재할당을 대표 시나리오로 검증한다.

### 2.2 이번 범위에서 제외 또는 결정이 필요한 항목

| ID | 항목 | 초안 처리 | 결정 필요 내용 |
|---|---|---|---|
| D-01 | 실제 로컬/외부 LLM 하이브리드 라우팅 | **MVP 포함** | 사용자가 로컬 Worker·OpenAI GPT·Anthropic Claude와 각 제공자의 사용 가능한 모델을 직접 선택한다. 선택은 데이터 민감도·사용자 허용 여부를 검증하고, 제공자·모델·선택 근거·실패 사유를 기록한다. |
| D-02 | 기기 사양 기반 스케줄링 | **MVP 포함** | 고도 예측 최적화가 아니라, 온라인·CPU/GPU/RAM 한도·모델 준비·작업 요구 조건으로 Worker를 선택하는 규칙 기반 배정을 MVP 수용 기준으로 한다. |
| D-03 | 다중 사용자 공유·외부 서버 확장 | 여유 시 추가 | 개인 소유 기기 중심 MVP가 조기 완료된 경우에만 진행한다. |
| D-04 | 기기 사양 수동 입력 | 높은 우선순위의 후순위 | MVP 핵심이 완료되면 자동 수집 실패 대응을 위해 구현한다. |

## 3. 유즈케이스 및 요구사항 정리

### 3.1 액터와 공통 제약

| 액터 | 역할 |
|---|---|
| 사용자 | 계정·기기·서비스를 관리하고 실행 결과를 확인하는 개인 사용자 |
| 중앙 서버 | 인증, DAG 검증, 작업 조율, 상태·이력 보관 |
| Worker Node | 사용자 기기에서 하트비트, 허용 폴더 검사, 모델 실행, 결과 반환 |
| 로컬/외부 LLM | 프롬프트 기반 워크플로우 생성 또는 작업 수행 모델. 데이터 민감도·사용자 동의에 따른 실제 라우팅 대상 |

- 서비스 구성은 DAG여야 하며 순환·실행 불가능한 연결은 저장 전 차단한다.
- Worker는 사용자가 지정한 폴더 화이트리스트 밖의 파일에 접근하거나 전송하면 안 된다.
- 실행 중 Worker가 끊기면 재할당하거나 사용자에게 실패 원인을 알려야 한다.

## 8. 확정된 우선순위와 다음 단계

1. **MVP:** D-01 실제 하이브리드 라우팅, D-02 기기 사양 기반 스케줄링, 여행 계획·개인 문서 기반 구직 준비 데모 2개.
